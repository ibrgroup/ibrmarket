# Система сидов (seeds) для backend API

Декомпозированная и расширяемая система наполнения БД тестовыми данными для всех сущностей API.

## Запуск

```bash
npm run seed
```

Перед сидированием по умолчанию **очищаются** все затронутые коллекции. Чтобы отключить очистку (добавлять данные к существующим):

```bash
SEED_CLEAR_EXISTING=false npm run seed
```

## Структура

- **`seeds/index.js`** — точка входа: подключение к БД, очистка (опционально), последовательный запуск сидеров, передача контекста между ними.
- **`seeds/data/`** — статические данные (пользователи, адреса, дерево категорий, пул товаров, блог, баннеры, слайдеры).
- **`seeds/seeders/`** — сидеры по сущностям, в порядке зависимостей:
  - `00-users.seed.js` — админ + обычные пользователи
  - `01-addresses.seed.js` — адреса доставки (Россия)
  - `02-categories.seed.js` — дерево категорий (родитель → подкатегория → третий уровень)
  - `03-products.seed.js` — товары с привязкой к категориям
  - `04-orders.seed.js` — заказы
  - `05-carts.seed.js` — корзины
  - `06-wishlists.seed.js` — избранное
  - `07-mylists.seed.js` — списки
  - `08-reviews.seed.js` — отзывы к товарам
  - `09-notifications.seed.js` — уведомления пользователей
  - `10-blogs.seed.js` — статьи блога
  - `11-banners.seed.js` — баннеры (bannerV1, bannerList2)
  - `12-homeSliders.seed.js` — слайдер главной
  - `13-logos.seed.js` — логотип

## Конфигурация

В **`config/seed.config.js`** и через переменные окружения:

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `SEED_USERS_COUNT` | Количество пользователей (кроме админа) | 25 |
| `SEED_ADDRESSES_PER_USER` | Адресов на пользователя | 2 |
| `SEED_PRODUCTS_COUNT` | Количество товаров | 200 |
| `SEED_ORDERS_PER_USER` | Заказов на пользователя | 3 |
| `SEED_CART_ITEMS` | Позиций в корзине на пользователя | 5 |
| `SEED_WISHLIST_ITEMS` | Позиций в избранном на пользователя | 8 |
| `SEED_MYLIST_ITEMS` | Позиций в «моём списке» на пользователя | 5 |
| `SEED_REVIEWS_PER_PRODUCT` | Отзывов на товар | 4 |
| `SEED_NOTIFICATIONS_PER_USER` | Уведомлений на пользователя | 10 |
| `SEED_BLOGS_COUNT` | Количество статей блога | 15 |
| `SEED_HOME_SLIDERS` | Слайдов на главной | 5 |
| `SEED_BANNER_V1_COUNT` | Количество баннеров bannerV1 | 8 |
| `SEED_BANNER_LIST2_COUNT` | Количество баннеров bannerList2 | 6 |
| `SEED_CLEAR_EXISTING` | Очищать ли БД перед сидированием | `true` |
| `SEED_VERBOSE` | Подробный лог | `false` |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | Учётные данные админа | admin@example.com / admin123 |

Пароль тестовых пользователей: **`user123`**.

## Добавление новых данных

1. **Новые статические записи** — добавить в соответствующий файл в `seeds/data/` (или новый файл и реэкспорт в `data/index.js`).
2. **Новый сидер** — создать файл в `seeds/seeders/` с экспортом `async function run(ctx, config)`, вернуть `{ name, count, created }`. Подключить сидер в `seeds/index.js` в массив `SEEDERS` и при необходимости добавить модель в `MODELS_FOR_CLEAR`.
3. **Новые параметры объёма** — добавить в `config/seed.config.js` в `seedData` и при необходимости в валидацию.

## Зависимости между сидерами

Контекст `ctx` передаётся по цепочке: пользователи → адреса (по `userId`), категории → товары (по `categoryByName`), пользователи + адреса + товары → заказы, пользователи + товары → корзины, избранное, отзывы, уведомления. Контент (блог, баннеры, слайдеры, лого) не зависит от пользователей/товаров.
